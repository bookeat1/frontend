# Тесты

## Как запустить

```bash
pnpm install          # один раз
pnpm test             # весь монорепозиторий, один прогон, без watch
pnpm test:watch       # локально, во время работы
pnpm check            # typecheck + lint + test — то же, что должно идти в CI
```

Один файл или один describe:

```bash
pnpm test apps/mobile/src/lib/__tests__/schedule.test.ts
pnpm test -t "deadline"
```

## Чем гоняем и почему

**Vitest** (`vitest.config.ts` в корне).

В репозитории три потребителя одного и того же TypeScript — Expo-приложение,
Next.js-панель и четыре общих пакета. `jest-expo` умеет только первое, то есть
означал бы два раннера и две схемы трансформации. Vitest берёт TS/TSX через
esbuild (ни babel-конфига, ни ts-jest) и покрывает все три.

React Native-компоненты рендерятся так же, как приложение уже рендерится в вебе:
`react-native` разрешается в `react-native-web` — это не тестовая заглушка, а
рабочая зависимость `apps/mobile` (на ней работает `expo start --web`). Плата за
единый раннер — нативные модули Expo приходится подменять явно; подмены лежат в
`test/stubs/` и читаются как обычный код, а не прячутся внутри пресета.

Условия прогона одинаковые везде: без watch, фиксированная таймзона
`Asia/Almaty`, и `fetch` подменён так, что **любой незаявленный сетевой запрос
падает с ошибкой**, а не висит и не проходит только на машине с VPN. Тесту,
которому нужен HTTP, положено подменить `fetch` самому.

## Где лежат тесты

Рядом с тем, что проверяют, в папке `__tests__`:

```
packages/api/src/__tests__/              маппинг ответов API, разбор ошибок
apps/mobile/src/lib/__tests__/           сессия, черновик брони, график работы
apps/mobile/src/components/**/__tests__/ логика экранов и рендер компонентов
apps/admin/src/components/__tests__/     экраны панели ресторана
```

Тестам панели нужен её алиас `@/*`; он продублирован в `vitest.config.ts` из
`apps/admin/tsconfig.json`. Компонент, который ходит в сеть, принимает клиента
пропом (см. `CapacityModeCard`) — общий `apiClient` берёт базовый URL из
окружения на этапе загрузки модуля и в тесте непригоден.

Внешние библиотеки в тестах — только объявленные в `package.json`.
`@testing-library/user-event` и `@testing-library/jest-dom` лежат в
`node_modules` как транзитивная зависимость `expo-router`; опираться на них
нельзя, поэтому события шлём через `fireEvent`, а утверждения пишем на
`textContent`/`value`.

Они попадают под те же `tsc --noEmit` и `eslint`, что и остальной код: тест,
который не проходит типизацию, — не тест.

## Правило

**Починка бага приезжает вместе с тестом, который поймал бы этот баг.**

Не «тестом на область» и не «тестом на модуль» — тестом, который падает на
исходном поведении и проходит на исправленном. Проверяется это ровно одним
способом: временно вернуть баг и посмотреть, как тест падает. Тест, падение
которого никто не видел, — не доказательство.

Что важно в формулировке теста:

- проверяем **границу**, а не середину диапазона (бесплатная отмена строго ДО
  дедлайна — значит нужны три случая: за миллисекунду до, ровно в, сразу после);
- «не знаем» — отдельный ожидаемый результат, а не разновидность «всё хорошо»;
- название теста говорит, что сломается у гостя, а не какая функция вызвана.

Каждый файл тестов начинается с комментария: какой именно баг он держит и чем
он кончился для гостя. Это единственная часть, которую читают, когда тест
однажды упадёт.

## Чего эти тесты не покрывают

- Экраны целиком (`app/**`) — они завязаны на `expo-router`, и поднять его в
  jsdom без правок приложения нельзя. Логика вынута туда, куда дотягиваются
  тесты (`cancellation-cost.ts`, `booking-draft.tsx`, `schedule.ts`); ветвление
  внутри `app/restaurant/[id]/book/index.tsx` остаётся непокрытым.
- Панель `apps/admin` — покрыт один экран (`CapacityModeCard`: разбор отказов
  переключения режима вместимости), остальные без тестов.
- Экран `app/profile.tsx` целиком — как и прочие маршруты. Логика вынесена в
  `src/lib/profile-edit.ts` и `src/components/profile/ProfileForm.tsx`; не
  покрыта только связка «сессия умерла → форму не размонтировать» внутри самого
  маршрута.
- Кэш фотографий. `expo-image` и набор иконок в jsdom не поднимаются (оба
  рассчитаны на то, что их TypeScript скомпилирует Metro), поэтому подменены —
  `test/stubs/expo-image.tsx` и `test/stubs/phosphor-react-native.tsx`. Отсюда
  главное ограничение: `cachePolicy`, `recyclingKey` и плавное появление
  фотографии — нативное поведение, тест видит только то, что приложение их
  запросило. Покрыто тестами другое: правило «что показывать в слоте фото»
  (`src/lib/photo-source.ts`) и то, что упавшее фото превращается в ту же
  плашку, что и отсутствующее, и больше не запрашивается. Работает ли кэш на
  самом деле — проверяется на телефоне.
- Настоящий бэкенд: все тесты работают на подменённом `fetch`. Контракт с живым
  API проверяется вручную (curl) и записывается в командной памяти.

## CI

Workflow заведён — `.github/workflows/ci.yml`, ровно три гейта на каждый push
и pull request: `pnpm run typecheck`, `pnpm run lint`, `pnpm run test`.

Внимание: корневой `.npmrc` (`node-linker=hoisted`) **не в гите**, а установка
на него опирается. Без него у CI будет другая раскладка `node_modules`, чем у
всех локально. Это надо решить отдельно — либо закоммитить `.npmrc`, либо снять
зависимость от hoisted-раскладки.
